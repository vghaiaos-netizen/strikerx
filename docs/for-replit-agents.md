# StrikerX — Guide for Replit Agents

Read this before touching any code.

---

## Production architecture

**Railway is production.** Replit is the development environment.

```
Replit (dev)  →  edit code  →  node scripts/github-push.mjs  →  GitHub (main)
                                                                      ↓
                                                               Railway auto-deploys
                                                               (permanent URL, always-on)
```

- The Railway URL (`*.up.railway.app`) is permanent — bots and BotFather are wired to it
- Do NOT try to use Replit Publish for production — use the Railway workflow above
- After every code change session, run `node scripts/github-push.mjs` to push to GitHub
  - Railway picks up the push and redeploys automatically (~3 min)
  - The Telegram bot webhooks re-register themselves on every startup

## Critical rules — do not break these

### Never touch generated files
- `lib/api-client-react/src/generated/api.ts` — generated by Orval
- `lib/api-zod/src/generated/api.ts` — generated by Orval
- To regenerate: `pnpm --filter @workspace/api-spec run codegen`
- Always edit `lib/api-spec/openapi.yaml` instead

### Never use console.log in server code
- Use `req.log` inside Express route handlers
- Use `logger` (from `artifacts/api-server/src/lib/logger.ts`) everywhere else

### Numeric columns from Drizzle return as strings
- Always wrap: `parseFloat(String(value))` or `Number(value)`
- Applies to: `commissionRate`, `totalEarned`, `currentAmountTon`, `strikerBalance`, `prizePoolTon`, etc.

### Bot webhook registration is centralised — do not duplicate
- Webhooks are registered ONLY in `app.ts` IIFE on startup
- Never add `setWebhook` calls to `gameBot.ts` or `groupBot.ts` — causes Telegram 429 errors

### Schema changes — never run on Railway with live data
- Dev: `pnpm --filter @workspace/db run push` (Drizzle push — safe, dev only)
- Production: write a manual `ALTER TABLE` SQL and run it against the Railway PostgreSQL
  - Get the connection string from Railway → PostgreSQL service → Connect tab

### match_event_active must be compared to `=== "true"`
- `getConfig()` returns `""` when the key is unset (not `null`, not `undefined`)
- Never use truthy check — always `=== "true"`

## Dev workflow step by step

### Starting a session

1. Check both workflows are running:
   - `API Server` (port 8000) — runs the Express server
   - `Start application` (port 5000) — runs Vite dev server
2. If either is stopped, restart it from the Replit workflow panel
3. After any server-side change, you must rebuild: the `API Server` workflow runs `build` before starting

### Making backend changes

```
Edit *.ts files in artifacts/api-server/src/
→ Restart the "API Server" workflow (it rebuilds automatically)
→ Test via curl or from the frontend
```

### Making frontend changes

```
Edit *.tsx files in artifacts/strikerx/src/
→ Vite HMR auto-reloads — no workflow restart needed
```

### Testing in the browser preview

The React app has a dev auto-login in `pages/home.tsx` (`useDevAuth` hook):
- When running in dev mode with no Telegram context, it auto-authenticates as player `123456`
- Username: `player_dev`, balance: 500 STRIKER (welcome bonus)
- Token clears itself on 401 and re-authenticates automatically

The dev auth bypass: `POST /api/auth/telegram` with `{ "initData": "dev:123456:player_dev" }` — only works in `NODE_ENV=development`.

### Admin dashboard in dev

1. Open `http://localhost:5000/admin` (or the Replit preview URL + `/admin`)
2. Log in with `ADMIN_USERNAME` / `ADMIN_PASSWORD` from Replit Secrets
3. Admin JWT is stored separately in `localStorage` as `strikerx_admin_token`

### Pushing to GitHub (required before Railway deploys)

```bash
node scripts/github-push.mjs
```

- Pushes all files atomically via GitHub GraphQL API
- Uses `GITHUB_PERSONAL_ACCESS_TOKEN` secret (already set in Replit)
- Repo: `github.com/vghaiaos-netizen/strikerx`
- Run from bash shell — NOT from the code_execution sandbox (PAT not available there)

## Domain detection (how the server finds its public URL)

All three files (`app.ts`, `gameBot.ts`, `groupBot.ts`) follow the same priority chain:

```
WEBHOOK_DOMAIN  →  REPLIT_DOMAINS  →  RAILWAY_PUBLIC_DOMAIN  →  REPLIT_DEV_DOMAIN
```

- On Railway: `RAILWAY_PUBLIC_DOMAIN` is auto-injected
- On Replit Publish: `REPLIT_DOMAINS` is auto-injected
- In Replit dev: `REPLIT_DEV_DOMAIN` is the rotating dev URL
- Manual override: set `WEBHOOK_DOMAIN` to any custom domain

## OpenAPI codegen — key type quirks

After editing `lib/api-spec/openapi.yaml`, regenerate with `pnpm --filter @workspace/api-spec run codegen`.

Known non-obvious type names (do not guess, use these exactly):
- `ReferralInfo.code` (not `referralCode`)
- `StreakInfo.streakDays` / `StreakInfo.canClaim` (not `currentStreak` / `canClaimToday`)
- `DepositInvoice.payLink` (not `payUrl`)
- `DepositInputCurrency`: `"TON"` | `"USDT_TON"` | `"BNB"` | `"SOL"` (uppercase)
- `WithdrawalInput.destinationAddress` (not `walletAddress`)

## Game architecture quick reference

| Game | Entry point | Notes |
|---|---|---|
| The Shot (crash) | `POST /ws` (WebSocket) | `crashEngine.ts` singleton — one round at a time |
| Penalty | `POST /api/games/penalty` | 1.92× payout, provably fair RNG |
| Minefield | `POST /api/games/minefield/start` → `/pick` → `/cashout` | Compound multiplier, session in DB |
| Free Kick | `POST /api/games/freekick` | Plinko-style, weighted outcomes |

All wins: multiplied by match event bonus (`getMatchEventBonus()`), then affiliate commission credited.
